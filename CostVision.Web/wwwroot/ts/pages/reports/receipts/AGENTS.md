# Отчёт по чекам

## Ответственность

API, фильтры, период, состояние, карточки и account actions организуют чтение и изменение размещения чеков.

## Контракты и границы

Не считать выбранный счёт доказательством доступа. Проверять согласованность после переноса/удаления и координацию ответов; дочерние папки отвечают за модалки и отдельные UI-компоненты.

API окна кандидатов операций возвращает PagedList<T> и передаёт page/pageSize вместе с прежними фильтрами. Общие суммы отчёта по-прежнему приходят с сервера; окно не обрезает список самостоятельно.

## Проверка

Сводка использует готовые TotalSum (расход) и IncomeSum (доход) сервера по всему выбранному набору; не пересчитывать её по номиналам текущей страницы. Неизвестные итоги отображать явно без подстановки нуля. ReceiptDto содержит OperationType; денежные агрегаты после деталей/refresh относятся к доступному документу, не только одной копии.

Проверка типов — npm run build:ts по корневым правилам. Поведение DOM, модальных окон, камеры и запросов требует отдельных сценариев; сборка не подтверждает браузерную приёмку.

## Сопровождение

Этот файл отвечает за собственные исходники непосредственно в данной папке; для дочерних папок действуют их локальные инструкции и общие правила родителей. После изменения исходников в этой папке сверить и актуализировать здесь ответственность, контракты, зависимости и способ проверки в рамках той же задачи. При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.

Общая карта и порядок сопровождения: [техническое руководство](../../../../../../Documentation/TechnicalGuide/12-source-map-and-maintenance.md). Открытые изменения: [план рефакторинга](../../../../../../Documentation/Plans/project-refactoring-2026-10-13/README.md).

API разворачивает только проверенный ServiceResult и проверяет обязательную форму данных через shared HTTP-validator: списки, поля результата и серверные страницы/итоги соответствующего сценария. Отказ не заменяется пустым успехом или нулевыми totals; финансовые расчёты остаются серверными. HttpError сохраняется до границы пользовательского действия. Начальные счета, список и детали независимы; фильтры/debounce/date change, hide/pagehide инвалидируют соответствующее чтение и AbortSignal. Summary/count/страницы принадлежат серверному актуальному ответу. Refresh/delete/move/remove захватывают ID/целевой счёт/тип действия до await и проверяют контекст списка/окна. Запоздалый hidden не очищает новую confirmation и не возвращает старое нижнее окно.

Изолированные requestCoordination.test.mts вызывают actual DOMContentLoaded/controller/API с подставным DOM/fetch и управляемыми Promise; браузер/HTTP/Bootstrap-приёмку этим не закрывать.
