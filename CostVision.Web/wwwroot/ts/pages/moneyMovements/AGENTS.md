# Страница денежных операций

## Ответственность

Модули связывают API, состояние, таблицу, диапазон дат, действия, подсказки и окно импорта.

## Контракты и границы

importModal показывает итоговые created/updated/error counts, сохраняет непринятые и неотправленные строки и исключает принятые clientRowId из следующей отправки до reload списка. Ошибки отправленного пакета переводятся в sourceLineNumber PDF; выявленный сервером дубль получает явный переключатель обновления комментария. Смена счёта после preview требует нового preview. Пока идёт сохранение, повторная отправка и закрытие окна блокируются; общий Bootstrap-стек сохранён. При изменении сверять обе стадии импорта, фильтры, права, гонки запросов и верхнюю модалку. tests/Frontend/moneyMovementImport.test.mts проверяет реальный контроллер с подставным DOM/fetch после build:ts; это не браузерная приёмка.

Основной список передаёт поиск и receiptFilter серверу, хранит одну страницу и показывает серверные суммы полного фильтра. Изменение ключа фильтров сбрасывает страницу; порядковый номер запроса защищает новый результат. Кандидаты имеют явную навигацию с количеством документов; Items включает все подходящие копии страницы. Связанные списки остаются отдельными. Поколения и отмена чтений поддерживают bounded read-контракт; декомпозиция 11 сохраняет этих владельцев в page session и отдельных контроллерах.

## Проверка

Динамическое поле комментария имеет id/name и aria-label. Модалки используют общий lifecycle 13; prevented hide при preview/save остаётся обязательным, shared dispose его не обходит. Изменение доступности не меняет финансовый/HTTP-контракт.

Общий ReceiptDto кандидатов содержит обязательный operationType, согласованный с сервером и отчётом чеков. Направление документа и финансовые итоги не вычислять запасной клиентской формулой.

Preview и Save одного окна не пересекаются: busy-состояние не позволяет позднему preview вернуть принятые строки после сохранения. Закрытие окна блокируется до ответа preview/save. Preview требует совпадения File object/bankId/accountId; изменение любого реквизита инвалидирует его. Forced disposal не принимает прежние строки/finally нового preview. После неизвестного save сохраняются непринятые строки, повтор заблокирован до сверки и нового preview; принимаемые clientRowId, PDF-номера ошибок и счётчики сохранены.

Проверка типов — npm run build:ts по корневым правилам. Поведение DOM, модальных окон, камеры и запросов требует отдельных сценариев; сборка не подтверждает браузерную приёмку.

## Сопровождение

Этот файл отвечает за собственные исходники непосредственно в данной папке; для дочерних папок действуют их локальные инструкции и общие правила родителей. После изменения исходников в этой папке сверить и актуализировать здесь ответственность, контракты, зависимости и способ проверки в рамках той же задачи. При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.

Общая карта и порядок сопровождения: [техническое руководство](../../../../../Documentation/TechnicalGuide/12-source-map-and-maintenance.md). Открытые изменения: [план рефакторинга](../../../../../Documentation/Plans/project-refactoring-2026-10-13/README.md).

API разворачивает только проверенный ServiceResult и проверяет обязательную форму данных через shared HTTP-validator: списки, поля результата и серверные страницы/итоги соответствующего сценария. Отказ не заменяется пустым успехом или нулевыми totals; финансовые расчёты остаются серверными. HttpError сохраняется до границы пользовательского действия. Начальные данные, основной список, linked/candidates/details используют отдельные поколения и AbortSignal; modal revision, hide/pagehide и смена фильтра исключают прежний ответ/ошибку. Команды захватывают ID/значения до await, Set блокирует повтор того же объекта/пары. Create/comment сохраняют изменённый draft; comment result/finally проверяют также identity DOM-редактора, чтобы повторное открытие того же ID не получило старый результат; записи не отменяются и не повторяются автоматически. Неизвестный исход требует обновить список и сверить факт записи.

Изолированные requestCoordination.test.mts вызывают actual DOMContentLoaded/controller/API с подставным DOM/fetch и управляемыми Promise; браузер/HTTP/Bootstrap-приёмку этим не закрывать.

index запускает controller; createMoneyMovementsSession создаёт собственные данные/locks/coordinators. bindings содержит DOM/modal/navigation refs; createCommand, commentCommands, receiptLinksController, accountActionsController владеют соответствующими сценариями с минимальными Pick зависимостями. Controller связывает фильтры/init/events; importModal сохраняет строгий отдельный preview/save lifecycle. dateRange реэкспортирует общий календарь, ReceiptDto общий с отчётом/магазинами. Same-ID editor, draft, pair locks и receiptsRevision сохраняются.
