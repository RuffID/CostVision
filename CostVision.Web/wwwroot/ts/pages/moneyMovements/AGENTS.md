# Страница денежных операций

## Ответственность

Модули связывают API, состояние, таблицу, диапазон дат, действия, подсказки и окно импорта.

## Контракты и границы

importModal показывает итоговые created/updated/error counts, сохраняет непринятые и неотправленные строки и исключает принятые clientRowId из следующей отправки до reload списка. Ошибки отправленного пакета переводятся в sourceLineNumber PDF; выявленный сервером дубль получает явный переключатель обновления комментария. Смена счёта после preview требует нового preview. Пока идёт сохранение, повторная отправка и закрытие окна блокируются; общий Bootstrap-стек сохранён. При изменении сверять обе стадии импорта, фильтры, права, гонки запросов и верхнюю модалку. tests/Frontend/moneyMovementImport.test.mts проверяет реальный контроллер с подставным DOM/fetch после build:ts; это не браузерная приёмка.

## Проверка

Общий ReceiptDto кандидатов содержит обязательный operationType, согласованный с сервером и отчётом чеков. Направление документа и финансовые итоги не вычислять запасной клиентской формулой.

Preview и Save одного окна не пересекаются: busy-состояние не позволяет позднему preview вернуть принятые строки после сохранения. Закрытие окна блокируется до ответа preview/save. Общая отмена запросов и жизненный цикл остальных страниц остаются отдельной задачей.

Проверка типов — npm run build:ts по корневым правилам. Поведение DOM, модальных окон, камеры и запросов требует отдельных сценариев; сборка не подтверждает браузерную приёмку.
