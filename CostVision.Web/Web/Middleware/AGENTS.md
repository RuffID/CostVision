# Неожиданные ошибки HTTP

## Ответственность

ExceptionHandlingMiddleware — единственный владелец неожиданных HTTP-ошибок, журналирует путь/TraceId без раскрытия exception клиенту. Unknown/internal OperationCanceledException даёт 500, TimeoutException — 504; ожидаемые provider/SQL ServiceResult не перехватываются заново.

## Контракты и границы

При RequestAborted ответ до начала очищается и получает 499 без тела; после начала клиентская отмена не пишет повторно. Иные ошибки после Response.HasStarted журналируются и пробрасываются хосту, без изменения статуса/headers/body. Для остальных ошибок до начала ответ очищается: JSON/AJAX получает success=false/message, HTML-навигация — общий HTML с ошибочным статусом. BadHttpRequestException сохраняет транспортный статус (например 400/413) с безопасным сообщением. Неожиданный сбой не становится успехом.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Web.UnitTests. HTTP-хост, браузер и production pipeline проверяются отдельным разрешённым контуром.
