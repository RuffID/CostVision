# Карта исходников и сопровождение

## Где искать реализацию

| Каталог | Содержание |
|---|---|
| `CostVision.Domain/Models` | Сущности авторизации, счетов, чеков, каталогов и операций |
| `CostVision.Domain/Models/Enums` | Допустимые роли, виды операций и состояния |
| `CostVision.Application/Abstractions` | Контракты хранения и внешних сервисов |
| `CostVision.Application/Models` | DTO, запросы, результаты и внутренние данные сценариев |
| `CostVision.Application/UseCases` | Правила доступа, создание, изменение, импорт и отчётность |
| `CostVision.Application/Extensions/FinancialDataAccess.cs` | Область финансового чтения и композиция выражений доступа для use case |
| `CostVision.Infrastructure/DataBase` | Контекст, конфигурации, репозитории и generated-миграции |
| `CostVision.Infrastructure/Services` | Внешний API, преобразование, QR/PDF, backup и фоновые задачи |
| `CostVision.Web/Pages` | Razor-каркас и HTTP-обработчики |
| `CostVision.Web/Web` | Авторизация, Options, middleware и HTTP-маппинг |
| `CostVision.Web/wwwroot/ts` | Собственный клиентский код |
| `CostVision.Web/wwwroot/ts/pages/dashboard`, `stores`, `reports/receipts`, `moneyMovements` | Entry/controller, независимые page sessions, bindings/render и контроллеры команд/окон этапа 11 |
| `CostVision.Web/wwwroot/ts/shared/receipts` | Общие DTO, транспорт и receipt workflow с явно переданным page context; локальный AGENTS.md |
| `CostVision.Web/wwwroot/ts/shared/dateRange.ts`, `preferences.ts`, `paging.ts` | Общий календарь, cookies/query page и прежние варианты навигации |
| `CostVision.Web/wwwroot/lib` | Готовые сторонние библиотеки, включая Chart.js и библиотеки QR/EXIF |
| `CostVision.Web/wwwroot/dist` | Сгенерированный JavaScript из TypeScript; не редактируется вручную |
| `tests` | Четыре .NET-проекта и изолированные node frontend-тесты с разными границами проверки |

При поиске дефекта следует пройти весь поток: страница → запрос → use case → доменная мутация → сохранение → DTO → клиент. Повторное использование mapper без фильтра доступа может вернуть лишние данные даже при правильной защите страницы.

## Локальные инструкции

Корневой [AGENTS.md](../../AGENTS.md) задаёт общие правила. Локальный AGENTS.md в каждой папке собственных исходников описывает её ответственность, важные контракты и подходящий уровень проверки. Инструкции родителей продолжают действовать; дочерний файл добавляет особенности своей зоны.

После изменения исходников нужно в той же задаче сверить и актуализировать соответствующий AGENTS.md. При добавлении или переносе папки нужно создать нового владельца описания и обновить прежнего. Если ответственность и контракты не менялись, нельзя добавлять фиктивные сведения или объявлять непройденные проверки успешными.

Такие файлы — сопровождаемая документация. Они не обновляются сами по событию сохранения .cs: обязательство закреплено для последующих изменений агентами и разработчиками.

## Исключения

Локальные инструкции не создаются в bin, obj, artifacts, node_modules, wwwroot/dist, стороннем wwwroot/lib, generated-миграциях и каталогах runtime-данных. DLL и скопированные vendor-ассеты не считаются собственными исходниками.

## Документы и планы

- Пользовательское правило обновляется в [Business](../Business/README.md).
- Реализация, технические ограничения и эксплуатация — в этом руководстве.
- Будущая работа, зависимости и приёмка — в [Plans](../Plans/README.md).
- Статус этапа меняется в его файле и таблице навигации после подтверждённого выполнения.

Solution содержит документационные разделы как элементы решения, а корневые README.md и AGENTS.md — в SolutionItems. Локальные AGENTS.md находятся непосредственно в папках исходников и отображаются внутри соответствующих проектов; отдельное дерево инструкций в solution не создаётся. При добавлении документа нужно обновить навигацию и CostVision.slnx; при переносе — проверить все относительные ссылки.

## Границы обновления

Описание должно соответствовать текущему коду. Планируемое изменение не записывается в локальные инструкции как уже действующий контракт. Прохождение unit-теста не заменяет проверку SQL, браузера, запуска и внешней интеграции. Для каждой выполненной проверки фиксируется её реальный контур.
