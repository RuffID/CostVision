# Реализация единицы работы

## Ответственность

UnitOfWorkScope владеет сохранением, transaction, commit/rollback и общим флагом отказа. ScenarioUnitOfWork делегирует технические операции; 14 узких adapters предоставляют только репозитории своего сценария.

## Контракты и границы

Не помещать сюда бизнес-выборки. Сверять отмену и исключения; атомарность SQL и защита от конкуренции требуют реальной реляционной проверки.

Перегрузка транзакции с IsolationLevel передаёт изоляцию в DatabaseFacade библиотечного IUnitOfWorkContext<CostVisionContextKey> и не сохраняет автоматически. Прежняя перегрузка остаётся с автоматическим SaveChangesAsync. SQL Server 2601/2627 преобразуются в ReceiptWriteConflictException для известного author identity index/PK_ReceiptAccounts и отдельно для IX_Products_NormalizedName/IX_Stores_NormalizedName_NormalizedAddress. AdaptiveName и неизвестные ограничения не входят в классификацию. Имя в значении ключа не считается именем ограничения. SQL Server 1205 внутри явной транзакции возвращается как отдельный конкурентный отказ, без скрытого повтора. DbUpdateConcurrencyException распространяется до workflow для Conflict; явная транзакция блокирует дальнейшее сохранение после любого отказа.

Все adapters одного DI scope делегируют одному UnitOfWorkScope; у них нет отдельных контекстов или флагов. Вложенная/конкурирующая транзакция отвергается до второго Begin. Даже перехваченный внутри action отказ Save не позволяет commit. После ошибки сохранения или транзакции scope нельзя использовать для следующего сохранения: rollback не сбрасывает change tracker. Повтор SaveChanges или любой перегрузки транзакции через другую обёртку даёт fail-fast. Новый DI scope независим. Подставное DbConnection проверяет вызов API и rollback, но не диапазонные блокировки SQL Server.

ProjectedReadQuery применяет predicate к IContextQueryRepository<TEntity, CostVisionContextKey>.Query(asNoTracking: true) и материализует переданную проекцию через ToListAsync(ct). Он не выбирает бизнес-фильтры, не исполняет SQL вручную и не создаёт контекст; CRUD/query адаптеры используют тот же marker и scoped tracker DLL. Прямого business context.Set/SaveChanges здесь нет; технический scope — единственный владелец библиотечного DatabaseFacade для transactions. Очистка tracker не сбрасывает проектный флаг отказа.

## Проверка

Чистые преобразователи и модель проверяются в Infrastructure.UnitTests; SQL, backup и hosted-компоненты — отдельными интеграционными проверками с требуемым разрешением.
