# Расчёт доходов и расходов

## Ответственность

Сценарий собирает доступные чеки и операции, фильтрует период, строит дневной/месячный ряд и нулевые точки.

## Контракты и границы

Use case группирует доступные копии по ReceiptIdentity, операции — по ID; проверяет доступ и выбранный счёт в одной связи. IncomeExpenseReportCalculator получает уже отфильтрованные данные и строит оба направления: receipts только чеки, moneyMovements только операции, комбинированный режим — платежи и непокрытые части документов.

ReceiptPaymentCoverage распределяет каждый рубль доступного выбранного платежа один раз по существующим связям того же направления. Приоритет у ранних документов; обратные рёбра позволяют перераспределить покрытие без уменьшения ранее покрытой суммы. Остаток относится к дате чека, платежи и переплата — к своим датам. Скрытая/исключённая операция документ не покрывает. Магазины ограничивают расход; закрытые связанные чеки не раскрывают магазины. Расчёт не мутирует связи и не заменяет matcher этапа 04.

Read-проекции передают только ReceiptIdentity, ID связей и scalar ID/date/amount/type операций. Каталог магазинов выбирается отдельно через DISTINCT, до расходного store-фильтра; неиспользуемый источник не читается. Membership проверяется в predicate без загрузки графа. Для точного глобального покрытия сохраняется весь отфильтрованный скалярный набор и его рёбра, без произвольного Take или замены алгоритма SQL-суммой. Несколько чтений не имеют общего snapshot.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.
