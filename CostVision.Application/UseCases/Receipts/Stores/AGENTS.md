# Магазины и их чеки

## Ответственность

Сценарии читают доступные магазины и чеки магазина, меняют адаптивное имя.

## Контракты и границы

Изменение и очистка общего AdaptiveName получают ID текущего пользователя. Нужен доступный чек с этим StoreId через FinancialDataAccess.WithReceiptReadAccess; знание ID и роль Admin не заменяют доступ. Отказ предшествует мутации и SaveChanges. Название остаётся общим для всех пользователей.

Чеки магазина проецируются с явным ID пользователя и доступными вложенными счетами/операциями. Счётчики кандидатов требуют текущего доступа к счёту операции, независимо от авторства; скрытые привязки чека не считаются отсутствием счёта. Загружать Account/Members связанных операций для корректных агрегатов.

Копии чеков группируются через типизированный Receipt.GetIdentity; строковое форматирование суммы и текущая культура не определяют состав групп. Расчёты агрегатов сохраняют прежний контракт.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.
