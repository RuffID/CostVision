# Товары и история покупок

## Ответственность

Сценарии читают товары из доступных чеков, покупки по магазинам и меняют адаптивное имя.

## Контракты и границы

Чтение получает Product либо ReceiptItem напрямую; изменение имени использует IProductNamingUnitOfWork (Product/Receipt). Общий projection 07 сохранён.

Изменение и очистка общего AdaptiveName требуют ID текущего пользователя и хотя бы одного доступного чека с этим ProductId. Предикат покупки использует FinancialDataAccess.WithReceiptReadAccess; системная роль Admin не обходит проверку. Проверять доступ до проверки глобального дубля и доменной мутации; отказ не вызывает SaveChanges. Имя остаётся общим, уникальность — глобальной, персональной схемы нет.

Список товара применяет доступ, период и доступность выбранного счёта в root predicate до проекции. SQL-композиция возвращает скалярные агрегаты и страницу, не историю ReceiptItems/Accounts/Members. ProductStorePurchases возвращает агрегаты магазин/вид единиц, без материализации истории и без молчаливого ограничения результата. Эквивалентный признак веса в ключе группировки согласован с ReceiptFinancialRules.

## Проверка

GetProductListUseCase и GetProductStorePurchasesUseCase используют ReceiptFinancialRules для количества и признака веса: граммы/1000, тонны×1000, килограммы и прочие единицы без изменения. Направления чеков и финансовое покрытие не вычислять отдельными формулами каталога.

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.
