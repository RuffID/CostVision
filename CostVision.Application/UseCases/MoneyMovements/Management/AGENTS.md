# Изменение денежных операций

## Ответственность

Сценарии создают, удаляют, переносят операции и меняют комментарий; валидатор проверяет роль счёта.

## Контракты и границы

Create получает IReceiptLinkUnitOfWork, comment/transfer — IMoneyMovementEditUnitOfWork, delete — IMoneyMovementRemovalUnitOfWork. Валидатор принимает только AccountMember repository; matcher получает MoneyMovement/Receipt напрямую и не открывает транзакцию. Все adapters используют общий scope.

Проверять исходный и целевой счёт, исполнителя и связи. Ожидаемый отказ не должен оставлять частичную запись; многошаговые изменения выполняются через UoW.

Валидатор разрешает мутации только Owner/Editor. Создание вызывает общий ExactMoneyMovementReceiptMatcher внутри Serializable; первая явная запись даёт ID операции, вторая сохраняет найденную связь. Перенос загружает ReceiptLinks/Receipt/Accounts внутри Serializable и до мутации проверяет общий целевой счёт либо собственный чек без счетов. Несовместимость требует ручной отвязки. Импортную операцию нельзя перенести в счёт с тем же импортным ключом. При отказе транзакции нужен новый scope; SQL-блокировки unit-тестами не подтверждаются.

CreateMoneyMovement вызывает общий валидатор с requireActive=true: Include Account, проверка архива до транзакции и записи. Исторические комментарии, удаление, перенос и связи используют прежнюю проверку прав без автоматического архивного запрета. Отсутствующая навигация для проверки архива является ошибкой контракта, а не разрешением.

Ответ создания передаёт текущего пользователя в MoneyMovementMapper. Не подставлять автора операции неявно для общих ответов и не раскрывать агрегаты недоступных связанных чеков.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.

## Сопровождение

Этот файл отвечает за собственные исходники непосредственно в данной папке; для дочерних папок действуют их локальные инструкции и общие правила родителей. После изменения исходников в этой папке сверить и актуализировать здесь ответственность, контракты, зависимости и способ проверки в рамках той же задачи. При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.
