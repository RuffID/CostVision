# Предпросмотр и сохранение выписки

## Ответственность

Сценарии выбирают банк, извлекают текст, строят preview, определяют дубли и сохраняют подтверждённые строки.

## Контракты и границы

Сохранение импорта требует requireActive=true у общего валидатора счёта. Архив отклоняется до обработки строк и открытия транзакции, включая ReplaceDuplicate. Предпросмотр и исторические изменения не получают этот запрет автоматически.

BankStatementRowKey содержит точные OccurredAt, Amount, Type и нормализованный ImportComment; операция и счёт не входят в идентичность строки. Preview и сохранение используют один типизированный ключ. Импорт удерживает локальный индекс только принятых строк до SaveChanges; повтор с заменой обновляет тот же объект. Created/Updated считаются по принятым строкам, Error — по отказам строк, номера ошибок — позиции в отправленном пакете.

DuplicateMoneyMovementId обязательно совпадает с единственным импортным дублем в счёте по полному ключу; неверный ID не разрешает создание или fallback-замену. Несколько старых дублей требуют ручной сверки. ReplaceDuplicate меняет только пользовательский комментарий; автор, исполнитель, ключ и связи сохраняются. Точная сумма должна помещаться в 18,2 без округления. Предикаты дубля и запись выполняются в Serializable с явным SaveChanges только при принятых изменениях. SQL-конкуренция остаётся отдельной приёмкой.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.
