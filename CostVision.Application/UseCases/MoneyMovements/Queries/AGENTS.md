# Списки операций и доступных счетов

## Ответственность

Сценарии обслуживают страницу операций, фильтры и выбор счёта.

## Контракты и границы

GetMoneyMovementList получает MoneyMovement/Receipt напрямую, GetMoneyMovementAccounts — Account напрямую. Сохранение и UoW этим read-only сценариям не передаются.

Операция читается только при текущем владении/участии в её счёте через FinancialDataAccess. Авторство операции не сохраняет чтение после исключения. Связанные чеки, их количество и сумма отдельно ограничиваются доступом к каждому чеку; для проекции загружать его Accounts/Members. Объём чтения ограничен query-композицией этапа 07.

Список счетов выбирает действующие доступные счета через FinancialDataAccess, загружает Members и определяет роль через GetRequiredAccountRole. Owner не подставляется при отсутствии membership; несогласованное владение даёт явную ошибку инварианта.

Список операций возвращает MoneyMovementListDto: скалярная страница, totalCount и раздельные incomeSum/expenseSum полного фильтра. Период, счёт, поиск по комментариям и фильтр видимых чеков задаются до агрегатов/Skip/Take; порядок OccurredAt DESC/Id. Membership используется в predicate, не материализуется для списка. Кандидатный count считается лишь для показанных операций по прежнему правилу точной календарной даты/суммы/счёта и свободных доступных копий.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.
