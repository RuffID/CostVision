# Создание и чтение сверки

## Ответственность

Сценарии связывают/отвязывают операции и чеки, читают связи и выполняют массовый точный подбор.

## Контракты и границы

Ручная связь использует IReceiptLinkUnitOfWork, auto — IReceiptReconciliationUnitOfWork, unlink — IMoneyMovementRemovalUnitOfWork. Читающие getters получают только нужные repositories напрямую. Matcher не владеет транзакцией; Create/Auto передают свои repositories в единственной Serializable-транзакции.

Чтение связей проверяет исходный объект и отдельно ограничивает связанные объекты через FinancialDataAccess в обоих направлениях. Доступ к чеку не даёт доступа к каждой операции; авторство операции не заменяет владение/участие в её счёте. Мапперы получают явный ID текущего пользователя. Массовый use case зарегистрирован, но не подключён к PageModel; это ограничение сохраняется.

ExactMoneyMovementReceiptMatcher общий для создания и массовой сверки: свободный расход и свободный Income-чек, календарная дата, точная сумма и общий счёт, один кандидат в обе стороны среди исходного набора. Обрабатываются только операции счетов с Owner/Editor membership; Viewer не создаёт связи. Несколько счетов одного чека не разрешают выбирать по порядку обхода. Чтения и явное сохранение выполняются внутри Serializable. Ручная привязка также читает совместимость и пару в Serializable, сохраняя разрешённые разные множественные связи. Уникальность пары не доказывает однозначность автоматической связи; SQL-приёмка обязательна.

Контракты обоих getter кандидатов возвращают PagedListDto<T>; связанные объекты по-прежнему возвращаются полным списком для исходного объекта. Обратные кандидаты считают страницы фискальных документов и сохраняют все подходящие копии выбранной identity.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.

После изменения исходников в этой папке сверить и актуализировать здесь ответственность, контракты, зависимости и способ проверки в рамках той же задачи. При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.
