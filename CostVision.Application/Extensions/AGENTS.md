# Регистрация сценариев Application

## Ответственность

ApplicationServiceCollectionExtensions регистрирует use case, workflow и банковские парсеры.

FinancialDataAccess задаёт проверки чтения счёта/чека и добавляет их к выражениям запросов. Подстановка параметров оставляет обычное дерево выражения без Invoke или Compile внутри запроса; SQL-перевод требует отдельной реляционной проверки.

В FinancialDataAccess методы оформлять обычными телами, проверки загруженных объектов — через if и циклы. Предикаты EF разделять на короткие именованные условия и явно соединять AndAlso/OrElse; лямбды с телом if/else нельзя преобразовать в Expression.

## Контракты и границы

Не добавлять запуск сценариев, БД или внешней сети в регистрацию. Сверять наличие интерфейса, реализации, lifetime и потребителя.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.

## Сопровождение

Этот файл отвечает за собственные исходники непосредственно в данной папке; для дочерних папок действуют их локальные инструкции и общие правила родителей. После изменения исходников в этой папке сверить и актуализировать здесь ответственность, контракты, зависимости и способ проверки в рамках той же задачи. При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.
