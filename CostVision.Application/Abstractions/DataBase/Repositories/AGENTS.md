# Контракт единицы работы

## Ответственность

IUnitOfWorkScope содержит только сохранение и две перегрузки транзакции. 14 сценарных интерфейсов предоставляют 2–4 нужных репозитория; их набор обоснован картой 07A. Глобального интерфейса со всеми репозиториями нет.

## Контракты и границы

Изменение сигнатур согласовать с Infrastructure UnitOfWorkScope, сценарными adapters и тестовыми фабриками. Не обходить общую транзакционную границу отдельным контекстом.

Перегрузка ExecuteInTransaction с IsolationLevel выполняет только action и commit: SaveChangesAsync явно вызывает сценарий. Прежняя перегрузка сохраняет автоматический SaveChanges после action. Для проверки и записи чеков применяется Serializable. ReceiptWriteConflictException — ожидаемый известный конфликт хранения; Application преобразует его в ServiceErrorType.Conflict, не перехватывая произвольные ошибки как дубли.

Общий IProjectedReadRepository<TEntity> добавлен по согласованию этапа 07. GetProjectedItemsAsync<TResult>(predicate, query, ct) сохраняет композицию на стороне вызывающего сценария; Infrastructure исполняет её без tracking через Query API поставленной DLL. Это общий read-контракт без специализированных выборок. Read-only получает минимальные repository-зависимости напрямую. EF/predicate/include и общий projection сохранены; изменение этой границы требует решения этапа 08.

## Проверка

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.

При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.
