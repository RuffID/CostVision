# Данные счетов, чеков и каталогов

## Ответственность

DTO используются карточками чеков, списками товаров и магазинов, покупками и формой совместного доступа.

## Контракты и границы

Вложенные записи не должны расширять права запроса. Общий каталог и персональное отображение не смешивать без явной модели.

ReceiptDto содержит только видимые счета и агрегаты видимых операций. Внутренний HasAccountLinks не входит в JSON и нужен исключительно для сохранения правила подбора операций к чеку без счёта после фильтрации вложенных счетов.

## Проверка

ReceiptDto передаёт OperationType; номинал TotalSum карточки сохраняется. В ReceiptListDto, StoreReceiptListDto и StoreListDto TotalSum означает расход полного выбранного набора, IncomeSum — доход. StoreListItemDto.TotalSpent — расход, IncomeSum — доход. Клиент отображает серверные итоги, не складывает номиналы текущей страницы. Денежные агрегаты документа объединяют только доступные копии и distinct ID операций.

Подходящие изолированные проверки находятся в tests/CostVision.Application.UnitTests. Собирать конкретный затронутый .csproj по корневым правилам; mock-репозитории не подтверждают SQL.

При переносе файлов обновить описания прежней и новой папок. Не добавлять фиктивный журнал или неподтверждённый результат проверки.
