# Проверки EF-модели без рабочей БД

## Ответственность

Тесты проверяют metadata конфигураций пользователей, счетов, чеков и операций.

## Контракты и границы

Это проверка построенной модели, не миграции и не фактической уникальности SQL. Изменение relationship согласовать с интеграционными сценариями.

Stage04MoneyPersistenceTests подтверждает отсутствие уникального импортного ключа, составной PK денежной связи и precision/длину полей. Реальный предикат ImportMoneyMovements переводится через ToQueryString в ru-RU/en-US без выполнения SQL. Эти проверки не подтверждают диапазонные блокировки, фактическую схему, колляцию или отсутствие конкурентного дубля.

Stage03ReceiptPersistenceTests проверяет фактические author index/PK, SQL-перевод идентичности через ToQueryString без выполнения и узкое распознавание имён ограничений. Stage03UnitOfWorkTests использует реальный DatabaseFacade и подставные DbConnection/DbTransaction: подтверждает передачу изоляции и обработку отказа, не отсутствие гонок на SQL Server. Открытая SQL-приёмка не закрывается этими тестами.

Синтетические SqlException создаются в тесте через внутренние конструкторы установленного SqlClient; при изменении версии проверять их сигнатуры. Это проверка классификации/rollback без SQL, а не доказательство фактических сообщений сервера или конкурентных исходов.

Stage07ReadQueryTests проверяет фактический API DLL и перевод root filters/count/totals/Skip/Take/групп всех затронутых чтений через SQL Server ToQueryString без соединения. ProjectedQueryCapture материализует только LINQ samples. Stage07ProjectionExecutionTests исполняет общий adapter через настоящую DI/DLL на подставном DbConnection, проверяя форму COUNT/страницы, тип результата, отмену и отсутствие tracking. Эти проверки не подтверждают реальные планы, строки, snapshot, collation или производительность.

## Проверка

Stage06RefreshPersistenceTests проверяет RowVersion/RefreshRevision metadata и SQL-перевод actual пакетного predicate/order/take/Guid cursor без соединения. Actual AddApplication/AddInfrastructure и поставленные DLL разрешаются в независимых scopes с разными ApplicationContext/UoW; hosting не запускается. Отдельный тест actual DLL выполняет пакетный запрос на подставном DbConnection и проверяет ORDER BY/TOP(32) без открытия реального соединения. Известные normalized-индексы распознаются отдельно от unknown/AdaptiveName; Stage03UnitOfWorkTests проверяет их перевод/rollback синтетическими SqlException. Это не применённая миграция или проверка конкуренции на двух соединениях.

Stage05ReportQueryTests передаёт actual predicate/include dashboard, getter кандидатов, отчётного счётчика и document projection деталей/refresh в SQL Server ToQueryString. Соединение не открывается, SQL не исполняется. Проверки перевода и наличия графа не доказывают фактическую материализацию, precision/collation, snapshot агрегатов или отзыв доступа.

Проверять тестовые утверждения и границы их изоляции; запуск выбирать по правилам родительского AGENTS.md. Не ослаблять ожидания и не сообщать о прохождении без выполнения.
