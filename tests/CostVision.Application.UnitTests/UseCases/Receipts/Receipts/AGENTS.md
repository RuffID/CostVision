# Проверки сценариев чека

## Ответственность

Тесты охватывают сущность, создание, чтение, удаление, ручной/фоновый refresh и workflow.

## Контракты и границы

После 07A фикстуры передают actual use case минимальные constructor-зависимости через TestUseCaseFactory. ITestStorage остаётся только набором test mocks; технические Save/transaction callbacks общие, production-контракта со всеми repositories нет.

Проверять повторы внутри QR-пакета, несовпадение внешних реквизитов, ошибки до мутации и retry. Mock-проверки не заменяют сохранение графа в SQL.

Создание чеков использует явную Serializable-перегрузку UoW без автоматического сохранения; фабрики подставного UoW должны выполнять action с исходным CancellationToken. Подробные проверки локального пакета и реальных predicate находятся также в Stage03RegressionTests в корне проекта тестов.

## Проверка

Подставные репозитории деталей/refresh должны выполнять дополнительный реальный предикат доступных копий identity для денежных агрегатов. Возвращать исходный чек независимо от predicate нельзя. Ручной refresh читает no-tracking снимок и передаёт ID пользователя workflow. Workflow-тесты выполняют явную Serializable-перегрузку без автоматического сохранения и проверяют повторную tracked-загрузку. Batch scope и регрессии находятся также в корне проекта тестов; ни один mock не доказывает SQL или реальный hosted lifecycle.

Проверять тестовые утверждения и границы их изоляции; запуск выбирать по правилам родительского AGENTS.md. Не ослаблять ожидания и не сообщать о прохождении без выполнения.
